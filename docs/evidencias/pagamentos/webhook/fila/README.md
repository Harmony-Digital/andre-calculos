# Processamento da fila de eventos de pagamento

O caso de uso server-only seleciona até 20 pagamentos da conta fictícia configurada pelo servidor e combina claim, consulta T e finalização Y. A seleção usa o relógio do banco e respeita disponibilidade e lease. Queries duráveis são retomadas sem novo GET; fonte nova ou revisão mais recente invalida o run anterior. Identidade divergente fica em quarentena; a mesma fonte reutiliza o run sob a barreira do pagamento. Evento ainda sem charge volta à seleção quando o vínculo aparece. Falha em um pagamento conserva recepção/consulta e permite continuar os outros itens.

A entrada GET `/api/cron/payment-webhooks` só funciona no perfil local fictício. Exige `ANDRE_WEBHOOK_FIXTURE_SCOPE_ID`, `ANDRE_WEBHOOK_FIXTURE_ACCOUNT_ID` e `ANDRE_WEBHOOK_FIXTURE_CRON_SECRET` de 32–255 caracteres, distinto de `ANDRE_WEBHOOK_FIXTURE_TOKEN`. Os valores são fornecidos pelo ambiente do processo. Nenhum scope, relógio ou parâmetro HTTP escolhe o destino. A resposta contém somente contagens; falha parcial retorna503. Credencial incorreta retorna401; parâmetros retornam400; produção/nuvem ou configuração ausente retornam503. A rota não foi publicada nem registrada como cron de produção.
